5Arrays, 2-D arrays, vector

int a[10];                    ← fixed, on stack, sizeof(a) = 40
int m[3][4];                  ← row-major: sizeof(m)=48, m[0]=16 B
std::array<int, 4> s{};       ← fixed + knows its size, no decay
std::vector<int> v = {1,2,3}; ← dynamic, on heap
v.push_back(4);  v[0];  v.at(9);  ← at() bounds-checks (throws)

6Why C needs pointers

  • functions get copies → to change the caller's data, pass its address · big objects: pass 8 bytes, not KBs
  • heap memory has no name → only reachable through a pointer · lists / trees = nodes pointing at nodes

pointer arithmetic: p + 1 moves by sizeof(*p) bytes (int* → +4) · a[i] == *(a + i)

7Array decay — and why

void f(int a[]) { sizeof(a); }  ← 8! a is really int*
int arr[10];  sizeof(arr);      ← 40 here
f(arr);                         ← arr "decays" to &arr[0]

why: C passes arrays by address (copying arrays was too costly in 1972) → size info is lost → pass length too, or use std::array / std::span<int> (C++20)

clang even warns: "sizeof on array function parameter will return size of int*"

3Memory in the quant hot path

  • never allocate on the hot path: malloc can take a lock, page-fault, or call the kernel (brk / mmap) → latency spikes (tail latency, p99)
  • pre-allocate at start-up, warm up (touch every page so no page faults later), reuse forever
  • measure the tail (p99, p99.9), not the average — one 50 µs stall loses the trade
★★★

4Frequent allocs vs pre-allocated pool

template<class T, size_t N> struct Pool {
  union Slot { Slot* next; alignas(T) unsigned char mem[sizeof(T)]; };
  Slot slots[N];  Slot* free_ = nullptr;          ← all memory up front
  Pool() { for (auto& s : slots) { s.next = free_; free_ = &s; } }
  template<class... A> T* make(A&&... a) {
    Slot* s = free_;  if (!s) return nullptr;      ← O(1), no syscall
    free_ = s->next;  return new (s->mem) T{std::forward<A>(a)...}; }
  void destroy(T* p) { p->~T();
    auto* s = reinterpret_cast<Slot*>(p); s->next = free_; free_ = s; }
};

free slots form a linked list inside the unused memory (free list) · destroy then make → reuses the same slot (verified) → hot in cache

★★

5Fragmentation & how to prevent it

fragmentation = free memory chopped into holes too small to use → allocs slow down / fail even though total free is enough

  • same-size objects in a pool (orders, messages) → any hole fits any object
  • arena / monotonic: bump a pointer, free everything at once (per request, per day)
  • vector.reserve(n) up front → one block, no regrow-copy-free cycle
  • keep long-lived and short-lived objects in different pools

3Rule of 3 / 5 / 0 — a tiny string

class Str { size_t n; char* d;        ← n first: init order = declaration order
public:
  Str(const char* s) : n(strlen(s)), d(new char[n + 1]) { memcpy(d, s, n + 1); }
  ~Str() { delete[] d; }                                   ← 1 dtor
  Str(const Str& o) : n(o.n), d(new char[n + 1]) { memcpy(d, o.d, n + 1); } ← 2 copy
  Str& operator=(Str o) noexcept { swap(o); return *this; } ← 3 copy-and-swap
  Str(Str&& o) noexcept : n(o.n), d(o.d) { o.d = nullptr; o.n = 0; }  ← 4 move
  void swap(Str& o) noexcept { std::swap(d, o.d); std::swap(n, o.n); }
};   // by-value operator= covers 5 (move =) too

own a resource → write all 5 (dtor, copy ctor, copy =, move ctor, move =) · own nothing raw → rule of 0 (use string / vector / unique_ptr, write none)

trap: members init in declaration order, not the order u list them · declare d before n and d(new char[n + 1]) reads garbage n (clang: -Wreorder-ctor, "n is uninitialized")

4Your own vector<T> (verified)

template <class T> class Vec { T* d_ = nullptr; size_t n_ = 0, cap_ = 0;
  void grow() { size_t nc = cap_ ? cap_ * 2 : 1;
    T* nd = static_cast<T*>(::operator new(nc * sizeof(T)));   ← raw bytes
    for (size_t i = 0; i < n_; i++) {
      new (nd + i) T(std::move_if_noexcept(d_[i]));  d_[i].~T(); }  ← move if safe
    ::operator delete(d_);  d_ = nd;  cap_ = nc; }
public:
  void push_back(const T& v) { emplace_back(v); }             ← copy in
  void push_back(T&& v)      { emplace_back(std::move(v)); }  ← move in
  template <class... A> T& emplace_back(A&&... a) {
    if (n_ == cap_) grow();
    return *new (d_ + n_++) T(std::forward<A>(a)...); }        ← perfect forwarding
  ~Vec() { for (size_t i = 0; i < n_; i++) d_[i].~T(); ::operator delete(d_); }
};

push_back("hello") · push_back(w) · emplace_back(3, 'x') · push_back(std::move(w)) → "hello world xxx …", size 4, cap 4, w now empty ✓

2Cache lines

  • memory moves in cache lines: 64 B on x86 (128 B on Apple M-series — this Mac reports 128) · touching 1 byte loads the whole line
  • sequential access → hardware prefetcher streams lines in · random / pointer chasing → a miss per hop
  • struct of 8-byte fields: 8 per line → keep hot fields together, cold fields elsewhere (hot / cold split)
struct A { char c; int i; char d; };   ← sizeof 12 (padding!)
struct B { int i; char c; char d; };   ← sizeof 8 — order fields big → small
struct alignas(64) C { int x; };       ← sizeof 64, starts on a line

3Virtual memory, paging, TLB

virtual address→ TLB hit? →physical framemiss →page-table walk (4 levels on x86-64)
  • every process sees its own address space · OS maps it in pages (4 KiB on x86 Linux; 16 KiB on this Mac)
  • TLB = cache of recent translations (~1–2 k entries) · miss = walk 4 levels of tables
  • huge pages (2 MiB / 1 GiB) → 1 entry covers 512× more → fewer TLB misses
  • first touch of a page = page fault (kernel maps it) → pre-fault / mlock at start-up

5Registers & assembly

8Interrupts, syscalls, kernel, epoll

  • interrupt: NIC / timer stops your core to run the kernel → jitter · fix: isolate cores (isolcpus), move IRQs away, pin threads (taskset)
  • syscall = user → kernel mode switch (read, write, send) · costly + cache pollution → batch, or kernel bypass (DPDK, Solarflare Onload / ef_vi)
  • file descriptor = small int indexing your process's open-file table · sockets, files, pipes, epoll itself are all fds
  • sockets = fds for network endpoints · epoll = ask the kernel which fds are ready (O(ready)) · busy-polling avoids sleeping at all

11malloc vs tcmalloc

  • glibc malloc (ptmalloc): arenas + free lists · small = from heap via brk, big (≥ 128 KiB) = own mmap · threads contend on arenas
  • tcmalloc (Google) / jemalloc: per-thread caches + size classes → most allocs never lock · link it in: -ltcmalloc or LD_PRELOAD
  • still: hot path should not allocate at all (page 3)

hot path = the few functions between packet-in and order-out → no allocs, no locks, no syscalls, no virtual, no exceptions, data in L1

  • keep a thread and its data on one node: numactl --cpunodebind=0 --membind=0 ./app
  • the NIC is attached to one socket → run the network thread there

2Data race → mutex

int plain = 0;  int guarded = 0;  std::mutex m;
auto work = [&]{ for (int i = 0; i < 1'000'000; i++) {
  plain++;                                    ← read-modify-write, unsafe
  { std::lock_guard<std::mutex> g(m); guarded++; }  ← unlocks at }
}};   // 2 threads: plain = 1,999,876 · guarded = 2,000,000 (measured)
  • data race = 2 threads touch the same memory, ≥ 1 writes, no sync → UB (lost increments here)
  • lock_guard = RAII lock, simplest · unique_lock = can unlock early, move, use with condition variables · scoped_lock(a, b) locks many without deadlock
  • deadlock: T1 holds A wants B, T2 holds B wants A → always lock in the same order

3Condition variable — producer / consumer

std::queue<int> q; std::mutex qm; std::condition_variable cv; bool done = false;
// producer (market data):
{ std::lock_guard g(qm); q.push(tick); }  cv.notify_one();
// consumer (strategy):
std::unique_lock lk(qm);
cv.wait(lk, [&]{ return !q.empty() || done; });   ← predicate!
while (!q.empty()) { use(q.front()); q.pop(); }

4Publish data with release / acquire

int data = 0;  std::atomic<bool> ready{false};
// producer

8Lock-free SPSC ring buffer

template<class T, size_t N> struct Spsc {
  using enum std::memory_order;              ← C++20: relaxed, acquire…
  std::array<T, N> buf;
  alignas(64) std::atomic<size_t> head{0};   ← consumer writes
  alignas(64) std::atomic<size_t> tail{0};   ← producer writes
  bool push(const T& v) { size_t t = tail.load(relaxed), n = (t + 1) % N;
    if (n == head.load(acquire)) return false;      ← full
    buf[t] = v;  tail.store(n, release);  return true; }
  bool pop(T& v) { size_t h = head.load(relaxed);
    if (h == tail.load(acquire)) return false;      ← empty
    v = buf[h];  head.store((h + 1) % N, release);  return true; }
};   // 100,000 pushes → sum 5,000,050,000 ✓

one producer, one consumer → no locks, no CAS · N power of 2 → & (N-1) instead of % · padding stops head / tail false sharing

2Inlining & constexpr

  • small, hot functions in headers → inlinable · virtual / function pointers / std::function → usually not

3Micro-optimisations

  • no temporaries / copies: const T&, move, emplace, string_view
  • no virtual in tight loops → CRTP / templates / std::variant + visit
  • hoist work out of loops · reserve containers · avoid exceptions on the hot path
  • branchless: s += (x >= 128) * x; · ternary often becomes a cmov · [[likely]] / [[unlikely]], __builtin_expect

1What an order book is

bids (buy)100.52 × 3 · 100.50 × 5 · 100.49 × 9best bid = highest
asks (sell)100.53 × 1 · 100.55 × 4 · 100.60 × 2best ask = lowest

2The data-structure ladder

designwhy

3Rules for the hot path

  • prices as int64 ticks (10052, not 100.52) · quantities as integers
  • order id → location in an unordered (flat) hash map for O(1) cancel
  • orders from a pre-allocated pool, no malloc per message
  • one thread owns the book · market data arrives via an SPSC queue
  • measure the latency distribution (p50, p99, p99.9), not just the average

4Matching an incoming buy (verified)

std::vector<Level> asks = {{10060, 2}, {10055, 4}, {10053, 1}};  ← best at back
std::vector<Fill> buy_limit(int64_t px, int64_t qty) {
  std::vector<Fill> fills;
  while (qty > 0 && !asks.empty() && asks.back().px <= px) {  ← crosses?
    Level& best = asks.back();
    int64_t q = std::min(qty, best.qty);
    fills.push_back({best.px, q});  qty -= q;  best.qty -= q;
    if (best.qty == 0) asks.pop_back();                     ← level gone
  }
  return fills;   ← leftover qty rests on the bid side
}

6Price levels, best at the back (verified)

struct Level { int64_t px; int64_t qty; };
struct Side { std::vector<Level> lv; bool bid;
  void add(int64_t px, int64_t q) {
    auto it = lv.end();
    while (it != lv.begin()) {                       ← search from the best
      auto p = std::prev(it);
      if (p->px == px) { p->qty += q; return; }      ← level exists
      if (bid ? p->px < px : p->px > px) break;      ← p is worse → insert here
      it = p;
    }
    lv.insert(it, {px, q});
  }
  const Level* best() const { return lv.empty() ? nullptr : &lv.back(); }
};

bids add 10050×5, 10052×2, 10049×9, 10052×1 → [10049x9, 10050x5, 10052x3] best 10052 · asks 10055, 10053, 10060 → best 10053 · spread 1 ✓

  • false sharing? → 2 cores writing different vars on one cache line
