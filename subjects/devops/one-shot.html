1Terminal vs Shell vs Linux

  • Terminal = window u type in · Shell = reads & runs ur cmds (bash, zsh) · Linux = an OS
  • Linux is an OS, Bash is a shell → not the same thing!
  • mac: default shell = zsh (bash script.sh still works). mac is Unix-like, NOT Linux
  • check: uname -a · echo "$SHELL" · bash --version · whoami

2Paths & folders

/ root (top of all)

~ my home folder

. here · .. parent

/etc config

/var logs, cache

/tmp temp stuff

/opt extra s/w

/usr tools, libs

home: /Users/u (mac)

  • Absolute path starts with / (full address) · Relative = from where u r now (pwd)
  • ls -la (shows hidden too) · cd .. · cd ~ · cd - (back to last dir) · mkdir -p a/b/c (makes parents too) · touch f.txt

3Files & text cmds

  • cat print · less scroll (q = quit) · head -n 20 first 20 · tail -n 20 last 20 · tail -f app.log = live logs
  • cp a b · cp -R dir1 dir2 · mv old new (move = rename) · rm f · rm -r dir · rmdir d (empty dir only)
  • rm skips Trash → gone forever. check the path before rm -r!
  • grep "ERROR" app.log · -i ignore case · -n line no.
  • find . -name "*.txt" · find . -type f (files only) · wc -l f count lines · file f what type

4Redirection & Pipes

streams: 0 = stdin (input) · 1 = stdout (output) · 2 = stderr (errors)

>output → file (overwrites!)
>>output → file (appends at end)
<take input from file · eg wc -l < notes.txt
2> · 2>>errors → file (overwrite · append) · 2>/dev/null = bin them
>out 2>erroutput & errors in diff files
>out 2>&1both in same file (2>&1 comes AFTER)
a | bstdout of a → stdin of b
tee fshow on screen + save to file (-a append)
  • pipe carries only stdout, not stderr. want both → cmd 2>&1 | grep x
  • eg ps aux | grep Terminal | wc -l · tip: grep X f > cat f | grep X

5Users & Permissions

r=4 w=2 x=1 → 7=rwx · 6=rw- · 5=r-x · 4=r--

755 = rwx r-x r-x (scripts) · 644 = rw- r-- r-- (normal files)

chmod u+x s.sh · chmod g-w f · chmod o+r f · chmod u=rw,go=r f (= 644)

on a fileon a dir

chown user:group f new owner · sudo cmd = run as admin · id = me + groups

6Processes & Services

  • process = a running program, has a PID. ps aux all · top live (q = quit)
  • sleep 60 & runs in bg · jobs list · fg %1 job 1 to front · Ctrl+C stop
  • kill PID = SIGTERM "please stop" · kill -9 PID = SIGKILL force (last option)
  • service = bg process the OS keeps running. process ≠ service
  • Linux: systemctl status|start|stop|restart|enable X (enable = start on boot)
  • mac uses launchd → launchctl list. no systemctl on mac!

7Script basics & variables

#!/bin/bash          ← shebang = which program runs it
name="Astro"         ✓ NO spaces around =
name = "Astro"       ✗ bash thinks name is a cmd
echo "Hi $name"      → Hi Astro   (double = expands)
echo 'Hi $name'      → Hi $name   (single = as it is)
echo "${name}Dude"   → AstroDude  ({} = where name ends)
dir="$(pwd)"         → cmd output saved in var
sum=$((5 + 3))       → 8  (math)
  • run → bash s.sh OR chmod +x s.sh then ./s.sh
  • vars are strings by default. always quote "$var" (safe with spaces)
★★

8if / else & tests

if [ "$age" -ge 18 ]; then echo "Adult"
elif [ "$age" -gt 0 ]; then echo "Minor"
else echo "Invalid"; fi

⚠ space after [ and before ] → [ "$a" -eq 1 ] ✓ ["$a" -eq 1] ✗

numbers-eq · -ne · -gt · -ge · -lt · -le (not = !)
strings= · != · -z empty · -n not empty
files-e exists · -f file · -d dir · -r read · -w write · -x exec
logic&& and · || or · ! not

[[ -d "$p" && -r "$p" ]] → [[ ]] = bash version, safer for combos

9Loops

for n in Astro Sam Alex; do echo "Hi $n"; done
for i in {1..5}; do echo "$i"; done     → 1 2 3 4 5
c=1; while [ "$c" -le 5 ]; do echo "$c"; c=$((c + 1)); done
  • while → update the var or it loops forever (Ctrl+C to escape)
  • break = exit loop now · continue = skip to next round

10Functions

greet() { echo "Hello, $1"; }
greet "Astro"                 → Hello, Astro
add() { echo "$(($1 + $2))"; }
res=$(add 10 20)              → res = 30
  • defining ≠ running → call it by name. $1 $2 inside fn = fn's own args
  • return = only a status 0–255 (0 = ok). want data back → echo + $(…)
  • local x=5 → x lives only inside the fn

11Script arguments

bash s.sh apple "big mango" →

$0 = s.sh · $1 = apple · $2 = big mango · $# = 2 (count)

"$@" = each arg separate ✓ (use in loops) · "$*" = all joined in 1 string

shift → drops $1, rest move left ($2 becomes $1)

12Exit status & errors

  • 0 = success, non-zero = fail · echo $? = last cmd's status
  • exit 1 ends the script · return 1 ends a fn · errors → stderr: echo "oops" >&2
  • set -u unset var = error · set -e stop on fail (not 100% reliable)
if [ "$#" -ne 1 ]; then
    echo "Usage: bash check.sh DIR" >&2; exit 1
fi

⚠ Exam traps — don't lose marks here

  1. > overwrites, >> appends
  2. pipe = stdout only
  3. dir r = list · dir x = enter
  4. x=5 ✓ · x = 5 ✗
  5. numbers → -eq, not =
  6. while: update var or ∞
  7. return = status, echo = data
  8. "$@" keeps args apart
  9. rm has no undo
  10. check cmd worked before saying "done ✓"

8Dockerfile + layer cache

COPY package*.json ./       deps list FIRST

9CMD vs ENTRYPOINT

docker run my-image other.py         → python other.py
docker run --entrypoint sh -it my-image

✓ use JSON form ["a", "b"] → app gets stop signals

1What is K8s?

  • K8s = container orchestrator → auto deploy · scale · network · heal containerized apps
  • keeps N replicas alive · replaces failed Pods · service discovery + LB · rolling update + rollback · config + storage
  • Docker builds/runs containers (Dockerfile) · K8s runs them across a cluster (YAML manifests) · still needs a runtime (containerd)
  • Declarative: u write desired state (3 replicas) → controllers keep reconciling actual → desired
IMP!!

2Architecture

Control plane 🧠

API Server front door (all go via it)

etcd key-value DB of cluster state

Scheduler picks a node for new Pods

Controller Mgr runs controllers

Worker node 💪

kubelet runs its Pods, reports status

runtime containerd / CRI-O

kube-proxy Service network rules

⚠ kubectl = just the CLI client, NOT part of control plane or node

apply → API Server → etcd → controllers make Pods → scheduler picks node → kubelet → runtime ▶

3Pods

  • Pod = smallest deployable unit · 1+ containers sharing network (same IP) → talk on localhost
  • same port twice ✗ · filesystem NOT auto shared · IP changes when replaced · lone Pod deleted → not recreated
  • Pending not set up yet · Running · Succeeded all exited ok · Failed · Unknown
  • CrashLoopBackOff, ImagePullBackOff = waiting reasons, NOT phases

4Labels & selectors

  • labels = key: value tags (app: backend) · selector = find by label
  • -l app=backend filter · -L app show as column · a=x,b=y = AND
  • app!=frontend → also matches Pods with NO app label
  • Services pick Pods by labels, not by Deployment name
PYQ ★

5ReplicaSet & Deployment

Deploymentmanages──▶ ReplicaSetkeeps N──▶ Pods 
apiVersion: apps/v1
kind: Deployment
spec:
  replicas: 3
  selector:
    matchLabels: {app: backend}       ← must match ↓
  template:
    metadata: {labels: {app: backend}}
    spec:
      containers: [{name: backend, image: nginx:stable}]
  • don't make a ReplicaSet directly → use a Deployment (rollout + rollback)
  • rolling update = swap old Pods → new bit by bit · maxSurge = extra Pods allowed · maxUnavailable = how many can be down
  • rollback = old Pod template, does NOT undo DB migrations
  • horizontal = more Pods · vertical = more CPU/RAM · cluster autoscaler = more nodes

6HPA (auto-scaling)

desired = ⌈ current × current metric ÷ target ⌉

eg 2 Pods at 90% CPU, target 60% → ⌈2 × 90/60⌉ = 3 Pods

  • needs Metrics Server (HPA won't install it) + CPU requests on containers
  • HPA doesn't add nodes → new Pods can stay Pending · not instant

ABasics & apply

  • kubectl apply -f deployment.yaml → create/update from YAML (declarative)
  • kubectl get nodes → list nodes in the cluster
  • kubectl get pods → list Pods
  • kubectl get pods -o wide → + node & Pod IP
  • kubectl describe pod <pod> → full details + Events
  • kubectl get events -A --sort-by=.metadata.creationTimestamp → all events, oldest → newest

BHandy flags

  • -n production → in that namespace
  • -A → all namespaces
  • -o wide · -o yaml → more columns · full YAML
  • -w → watch live
  • -c <container> → pick container (multi-container Pod)

CLabels & selectors

  • kubectl get pods --show-labels → show all labels
  • kubectl get pods -l app=backend → filter by label
  • kubectl get pods -l app=backend,environment=production → AND of both
  • kubectl get pods -l 'app!=frontend' → not frontend (incl. no label)
  • kubectl get pods -L app → show app as a column
IMP!!

DDeployments & ReplicaSets

  • kubectl get deployments → list Deployments
  • kubectl get replicasets → list ReplicaSets
  • kubectl scale deployment backend --replicas=5 → set to 5 Pods
  • kubectl set image deployment/backend backend=nginx:1.28 → new image → rolling update
  • kubectl rollout status deployment/backend → is the rollout done?
  • kubectl rollout history deployment/backend → list old revisions
  • kubectl rollout undo deployment/backend → rollback to previous

EAutoscaling (HPA)

  • kubectl autoscale deployment backend --cpu-percent=60 --min=2 --max=10 → make an HPA
  • kubectl get hpa → list HPAs (target vs current)
  • kubectl get hpa -w → watch it scale
  • kubectl describe hpa backend → details + scaling events
★★

FServices & endpoints

  • kubectl get services · kubectl get svc -n production → list Services
  • kubectl describe service backend → selector, ports, endpoints
  • kubectl get service backend -o yaml → full YAML
  • kubectl get endpoints backend → which Pod IPs it sends to
  • kubectl get endpointslices -l kubernetes.io/service-name=backend → its EndpointSlices

GDNS check

  • kubectl get pods -n kube-system -l k8s-app=kube-dns → are CoreDNS Pods up?
  • kubectl get services -n kube-system → kube-dns Service
  • nslookup backend.production → resolve name (run inside a Pod)

HIngress

  • kubectl get ingress → list Ingress rules
  • kubectl describe ingress backend-ingress → hosts, paths, backends

IConfigMaps & Secrets

  • kubectl apply -f configmap.yaml → create/update it
  • kubectl get configmap → list ConfigMaps
  • kubectl describe configmap backend-config → see its keys & values
  • kubectl get secret → list Secrets
  • kubectl describe secret backend-secret → keys only, values hidden

JStorage

  • kubectl get pvc → claims + status (Bound / Pending)
  • kubectl describe pvc database-storage → why Pending? → Events
  • kubectl get pv → actual volumes
  • kubectl get storageclass → storage types available
★★

KLogs & debug

  • kubectl logs <pod> → container output
  • kubectl logs <pod> --previous → logs of the crashed run
  • kubectl logs -f <pod> → follow live
  • kubectl logs <pod> -c <container> → one container
  • kubectl exec -it <pod> -- sh → shell inside the Pod
  • curl -v http://backend.production:8080/ → test from inside a Pod
all the best!! 🤞
