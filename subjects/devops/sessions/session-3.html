1 Scripts, Variables & Quoting

Explain like I'm 5

A shell script is the list of commands you'd type, saved in a file, so the computer can type them for you — the same way, every time.

  • Line 1 is the shebang: which interpreter runs the file. #!/usr/bin/env bash finds bash on PATH (portable); #!/bin/bash hard-codes the path.
  • Make it executable once with chmod +x, then run it with ./name.sh.
hello.sh
#!/usr/bin/env bash
# hello.sh - first script
echo "Hello from $(hostname), I am $(whoami)"
echo "Today is $(date +%A)"
$ ./hello.sh
bash: ./hello.sh: Permission denied
$ chmod +x hello.sh
$ ./hello.sh
Hello from web-01, I am shaurya
Today is Friday

$ cat vars.env

Common mistake: sh script.sh on Ubuntu

/bin/sh is dash, not bash, so bash features break — and the script may carry on with exit 0:

$ sh shtest.sh
shtest.sh: 3: [[: not found

Run bash scripts with ./script.sh or bash script.sh.

2 Arguments

Explain like I'm 5

Arguments are the words you say after the script's name — like telling a vending machine which button you pressed.

VariableHolds
$0Script name as it was called (./args.sh)
$1 … $9, ${10}Positional arguments (braces needed from 10)
$#Number of arguments
"$@"All arguments, each kept as a separate word — use this 99% of the time
"$*"All arguments joined into one string
$?Exit status of the last command
$$ / $!PID of this script / of the last background job
args.sh
#!/usr/bin/env bash
echo "script name : $0"
echo "first arg   : $1"
echo "second arg  : $2"
echo "arg count   : $#"
echo "PID         : $$"
echo '--- for a in "$@"'
for a in "$@"; do echo "  [$a]"; done
echo '--- for a in "$*"'
for a in "$*"; do echo "  [$a]"; done
echo '--- for a in $*'
for a in $*; do echo "  [$a]"; done
shift                             # drop $1; $2 becomes $1
echo "after shift : \$1=$1  \$#=$#"
$ ./args.sh "my file.txt" prod 42

Validate before doing anything

deploy.sh
#!/usr/bin/env bash
# deploy.sh <environment> [version]
if [[ $# -lt 1 ]]; then
  echo "Usage: $0 <environment> [version]" >&2   # errors go to stderr
  exit 1                                          # non-zero = failure
fi
ENV="$1"
VERSION="${2:-latest}"            # optional 2nd arg with a default
echo "Deploying taskflow-api:$VERSION to $ENV"
$ ./deploy.sh; echo "exit=$?"
Usage: ./deploy.sh <environment> [version]
exit=1
$ ./deploy.sh staging
Deploying taskflow-api:latest to staging
$ ./deploy.sh prod 1.4.0
Deploying taskflow-api:1.4.0 to prod
Key takeaway

Every script that takes arguments should check $# first, print a Usage: line to stderr (>&2) and exit 1. Loop over arguments with for a in "$@" — the quotes keep "my file.txt" in one piece.

Recap $1..$9 positional, $# count, "$@" all (separate), "$*" all (joined), shift drops the first, ${2:-default} for optional args.

  start|up)   echo "starting taskflow" ;;

Common mistakes
  • Missing spaces: if [[$X == 1]] → [[1: command not found. Spaces are required inside the brackets.
  • a && b || c is not a true if/else: if b fails, c runs too. Use if when b can fail.
  • Comparing numbers with > inside [[ ]] (string order, so 10 < 9). Use -gt or (( )).
Recap 0 = success. if cmd; then tests an exit code; [[ ]] for files (-f -d -x), strings (-z = =~) and numbers (-eq -gt); &&/|| for short chains; case for matching one value against patterns.

4 Loops

Explain like I'm 5

A loop is "do this for each one": for each server, for each log file, for each line — or "keep trying until it works".

loops.sh
#!/usr/bin/env bash
for svc in api db web; do                     # 1. over a list of words
  echo "checking taskflow-$svc"
done

for f in /var/log/taskflow/*.log; do          # 2. over files (glob)
  echo "$(basename "$f"): $(wc -l < "$f") lines"
done

for ((i = 1; i <= 3; i++)); do                # 3. C-style counter
  echo "attempt $i"
done

echo {1..5}                                   # brace expansion
echo {01..10..3}                              # zero-padded, step 3
echo server-{a,b,c}
seq -s ' ' 2 2 10                             # seq FIRST STEP LAST

readloop.sh
#!/usr/bin/env bash
while read -r name ip; do                     # read 2 fields per line
  [[ -z "$name" || "$name" == \#* ]] && continue   # skip blank and comment lines
  echo "$name -> $ip"
done < servers.txt                            # feed the file into the loop

count=0
until [[ $count -ge 3 ]]; do                  # until = loop while condition is FALSE
  count=$((count + 1))
  echo "until: count=$count"
done

for code in 200 200 500 200 404; do
  [[ $code == 200 ]] && continue              # skip to next iteration
  echo "first non-200: $code"
  break                                       # leave the loop
done
$ ./readloop.sh

web-02 -> 10.0.1.11
db-01 -> 10.0.2.20
until: count=1
until: count=2
until: count=3
first non-200: 500
  • read -r: -r keeps backslashes literal. Use while IFS= read -r line to keep leading spaces too.
  • read -r name ip splits each line on whitespace: field 1 → name, the rest → ip.
Common mistakes 
$ total=0; cat servers.txt | while read -r line; do total=$((total + 1)); done; echo "total=$total"
total=0                     # the piped loop ran in a subshell; its variables are lost
$ total=0; while read -r line; do total=$((total + 1)); done < servers.txt; echo "total=$total"
total=4
$ n=3; echo {1..$n}            # brace expansion happens BEFORE variables expand

$ seq 1 "$n" | tr '\n' ' '      # use seq or for ((i=1; i<=n; i++)) instead
1 2 3 
$ for f in /var/log/none/*.log; do echo "got: $f"; done
got: /var/log/none/*.log     # no match → the pattern itself; add shopt -s nullglob

Also avoid for f in $(ls) — it breaks on spaces. Loop over a glob (for f in *.log) instead.

Recap for x in list / for f in *.log / for ((i=1;i<=n;i++)); while read -r … done < file for lines; until loops while false; continue skips, break exits. {1..5} needs literal numbers.

5 Functions

Explain like I'm 5

A function is a mini-script with a name inside your script. Write it once, call it as many times as you like.

  • Define with name() { …; } (or function name { …; }) before you call it. Call it like a command: greet Riya SRE.
  • Inside a function $1, $2, $#, "$@" are the function's arguments, not the script's.
  • Variables are global by default; declare them with local.
funcs.sh
#!/usr/bin/env bash
greet() {
  local name="$1"                       # $1 inside a function = the function's 1st arg
  local role="${2:-developer}"
  echo "Hi $name ($role), you passed $# arg(s)"
}

is_port_open() {                        # answer via EXIT STATUS (0 = yes)
  local port="$1"
  ss -tln | grep -q ":${port} "
}

disk_usage() {                          # answer via OUTPUT (capture with $(...))
  df --output=pcent "${1:-/}" | tail -1 | tr -dc '0-9'
}

greet Shaurya
greet Riya "SRE"

if is_port_open 3000; then
  echo "port 3000: something is listening"
else
  echo "port 3000: free"
fi

used=$(disk_usage /)
echo "root disk is ${used}% used"

counter=0
bump() { counter=$((counter + 1)); local temp="gone"; }
bump; bump
echo "counter=$counter temp=${temp:-<unset>}"   # globals change, locals vanish
$ ./funcs.sh
Hi Shaurya (developer), you passed 1 arg(s)
Hi Riya (SRE), you passed 2 arg(s)
port 3000: something is listening
root disk is 31% used
counter=2 temp=<unset>

Outputecho the value; capture with x=$(func)Data: a number, a path, a version string

Common mistake: returning a string 
$ get_version() { return "1.4.0"; }; get_version; echo "status=$?"
bash: return: 1.4.0: numeric argument required
status=2

return only sets an exit code. Print the value instead: get_version() { echo "1.4.0"; } → v=$(get_version). Inside a captured function, send log messages to stderr (echo "msg" >&2) or they end up in the captured value.

Recap name() { local x="$1"; … }. Answer yes/no via exit status, data via echo + $(…). Always use local for internal variables.

7 Automation Scripts & cron

Explain like I'm 5

We write two robot helpers — one packs a backup every night, one pokes TaskFlow every 2 minutes and restarts it if it doesn't answer — and cron is the alarm clock that wakes them.

Script 1: backup.sh

Archives any number of directories into timestamped .tar.gz files, deletes archives older than 7 days, logs everything, and exits non-zero if anything failed.

/opt/taskflow/scripts/backup.sh
#!/usr/bin/env bash
#
# backup.sh - archive one or more directories into timestamped .tar.gz files
#             and delete archives older than RETENTION_DAYS.
#
# Usage:   backup.sh <backup_dir> <source_dir> [source_dir ...]
# Example: backup.sh /var/backups/taskflow /opt/taskflow /etc/taskflow
# Env:     RETENTION_DAYS (default 7), LOG_FILE (default /var/log/taskflow/backup.log)

set -euo pipefail                            # stop on errors, unset vars, failed pipes
umask 077                                    # archives can contain secrets -> owner-only files

RETENTION_DAYS="${RETENTION_DAYS:-7}"
LOG_FILE="${LOG_FILE:-/var/log/taskflow/backup.log}"
TIMESTAMP="$(date +%Y%m%d-%H%M%S)"           # e.g. 20261009-023000

log() {                                      # usage: log LEVEL message...
  local level="$1"
  shift                                      # drop LEVEL; "$*" is now the message
  echo "$(date '+%Y-%m-%d %H:%M:%S') [$level] $*" | tee -a "$LOG_FILE"
}

usage() {
  echo "Usage: $(basename "$0") <backup_dir> <source_dir> [source_dir ...]" >&2
  exit 1
}

backup_dir() {                               # usage: backup_dir SOURCE DEST
  local src="${1%/}"                         # strip a trailing slash
  local dest="$2"
  local name archive size

  if [[ ! -d "$src" ]]; then
    log WARN "skipping '$src' (not a directory)"
    return 1
  fi

  name="$(echo "${src#/}" | tr '/' '_')"     # /opt/taskflow -> opt_taskflow
  archive="${dest}/${name}-${TIMESTAMP}.tar.gz"

  if ! tar --exclude='node_modules' -czf "$archive" -C "$(dirname "$src")" "$(basename "$src")"; then
    log ERROR "tar failed for '$src'"
    return 1
  fi
  size="$(du -h "$archive" | cut -f1)"
  log INFO "created $archive ($size)"
}

# ---- 1. validate input ----
[[ $# -ge 2 ]] || usage
if ! [[ "$RETENTION_DAYS" =~ ^[0-9]+$ ]]; then
  echo "Error: RETENTION_DAYS must be a whole number (got '$RETENTION_DAYS')" >&2
  exit 1
fi

DEST="$1"
shift                                        # now "$@" = only the source dirs
mkdir -p "$DEST" "$(dirname "$LOG_FILE")"

# ---- 2. back up every source directory ----
log INFO "backup started: $# source(s) -> $DEST"
failed=0
for src in "$@"; do
  backup_dir "$src" "$DEST" || failed=$((failed + 1))
done

# ---- 3. delete archives older than RETENTION_DAYS ----
find "$DEST" -maxdepth 1 -type f -name '*.tar.gz' -mtime +"$RETENTION_DAYS" -print -delete |
  while IFS= read -r old; do
    log INFO "deleted old backup $old"
  done

# ---- 4. summary + exit code ----
if (( failed > 0 )); then
  log ERROR "finished with $failed failure(s)"
  exit 1
fi
log INFO "backup finished OK"
Line(s)Why
set -euo pipefailStop on the first failure, on unset variables, and on failures inside pipes.
umask 077The archives contain .env / taskflow.env secrets → files are created rw-------.
RETENTION_DAYS="${RETENTION_DAYS:-7}"Configurable from the environment with a default: RETENTION_DAYS=30 ./backup.sh ….
TIMESTAMP="$(date +%Y%m%d-%H%M%S)"Computed once, so every archive of one run shares it; names sort chronologically.
log()local level="$1"; shift → the rest of the arguments ($*) is the message. tee -a prints it and appends to the log file.
usage()Usage text to stderr (>&2), exit 1.
local src="${1%/}"Accept /etc/taskflow/ or /etc/taskflow.
return 1 (not exit)A bad source is reported, but the other directories still get backed up.
tr '/' '_'Unique names: with plain basename, /opt/taskflow and /etc/taskflow would both be taskflow-… and overwrite each other.
tar --exclude=… -czf … -C "$(dirname)" "$(basename)"--exclude before the path (Session 2 gotcha); -C stores taskflow/… instead of absolute paths.
if ! tar …; thenset -e is switched off inside a function called as part of || (the loop line), so tar's result is checked explicitly.
[[ $# -ge 2 ]] || usageNeed a destination plus at least one source.
=~ ^[0-9]+$Reject RETENTION_DAYS=abc before it reaches find.
DEST="$1"; shiftAfter shift, "$@" is just the source list.
|| failed=$((failed + 1))Count failures without aborting the loop.
find … -mtime +"$RETENTION_DAYS" -print -delete | while readDelete old archives and log each name. -mtime +7 = older than 7 whole days (an 8-day-old file matches; a 7.5-day-old one doesn't).
(( failed > 0 )) → exit 1Callers (cron, CI, monitoring) can see that the backup was incomplete.

Script 2: healthcheck.sh

Calls TaskFlow's /health; after 3 failed attempts it restarts the systemd service and checks again.

/opt/taskflow/scripts/healthcheck.sh
#!/usr/bin/env bash
#
# healthcheck.sh - check TaskFlow's /health endpoint and restart the service if it is down.
# Run as root (systemctl restart needs it), e.g. from root's crontab every 2 minutes.
# Exit codes: 0 = healthy or recovered, 1 = still down after a restart

set -uo pipefail                 # no -e: a failing curl is expected here and handled below

URL="${HEALTH_URL:-http://localhost:3000/health}"
SERVICE="taskflow"
RETRIES=3                        # attempts before restarting
WAIT=5                           # seconds between attempts
LOG_FILE="/var/log/taskflow/healthcheck.log"

log() {
  echo "$(date '+%Y-%m-%d %H:%M:%S') $*" >> "$LOG_FILE"
}

http_status() {                  # prints the HTTP status code; 000 = could not connect
  curl -s -o /dev/null -w '%{http_code}' --max-time 3 "$URL"
}

for ((i = 1; i <= RETRIES; i++)); do
  code="$(http_status)"
  if [[ "$code" == "200" ]]; then
    exit 0                       # healthy: stay quiet so the log doesn't grow every run
  fi
  log "WARN attempt $i/$RETRIES: $URL returned $code"
  sleep "$WAIT"
done

log "ERROR $SERVICE is down - restarting"
systemctl restart "$SERVICE"
sleep "$WAIT"

code="$(http_status)"
if [[ "$code" == "200" ]]; then
  log "RECOVERED $SERVICE is healthy again"
  exit 0
fi
log "CRITICAL $SERVICE still down after restart (HTTP $code)"
exit 1
Line(s)Why
set -uo pipefail (no -e)A failing curl is the normal "down" case; we handle it instead of dying.
URL="${HEALTH_URL:-…}"Point it elsewhere for testing: HEALTH_URL=http://localhost:4000/health ./healthcheck.sh.
curl -s -o /dev/null -w '%{http_code}' --max-time 3Silent, discard the body, print only the status code, never hang more than 3 s. Connection refused prints 000 (curl exit 7).
for ((i = 1; i <= RETRIES; i++))Retry 3× with 5 s gaps so one slow response doesn't trigger a restart.
exit 0 when healthyQuiet on success; the log only records problems.
systemctl restart "$SERVICE"Needs root → schedule it in root's crontab.
Final check + exit 1Exit status tells cron/monitoring whether self-healing worked.
 
$ sudo systemctl stop taskflow                          # simulate a crash

2026-10-09 11:10:15 ERROR taskflow is down - restarting
2026-10-09 11:10:20 RECOVERED taskflow is healthy again
$ sudo bash -x /opt/taskflow/scripts/healthcheck.sh 2>&1 | tail -5   # healthy run, traced

++ curl -s -o /dev/null -w '%{http_code}' --max-time 3 http://localhost:3000/health

Worst case runtime: 3 × (3 s timeout + 5 s wait) + 5 s + 3 s ≈ 32 s, well under the 2-minute schedule. If a job could overlap with its next run, wrap it: flock -n /run/healthcheck.lock /opt/taskflow/scripts/healthcheck.sh.

LineWhy
SHELL=/bin/bashcron runs commands with /bin/sh (dash) by default.
PATH=…cron's default PATH is only /usr/bin:/bin. Anything in /usr/local/bin or /usr/sbin is "command not found" without this.
MAILTO=""Don't try to email output (most servers have no mail setup; cron logs No MTA installed, discarding output).
>> …/backup-cron.log 2>&1Keep stdout and errors from each run; otherwise they're lost.
Comments on their own linecron only treats # at the start of a line as a comment. FOO=bar # note really sets FOO to bar # note; on a job line the text is handed to the shell with the command (and any % in it is still mangled).

Why "it works in my terminal but not in cron"
  • PATH: cron has /usr/bin:/bin only → aws: command not found. Set PATH= in the crontab or use absolute paths (/usr/local/bin/aws).
  • % is special in crontab (it means newline). echo "run at $(date +%F)" gets cut at the % — cron logged CMD (echo "run at $(date +) and nothing was written. Escape it as \%, or move the command into a script.
  • No environment: no ~/.bashrc, different working directory, no variables you exported in your shell. Use absolute paths and set what you need in the script.
  • Output vanished: redirect it (>> file 2>&1).
  • /etc/cron.d rules: file must be owned by root (cron logs WRONG FILE OWNER), not group/world-writable, and the name may not contain a dot — taskflow.cron is silently ignored.
  • Day-of-month and day-of-week both set (e.g. 0 0 13 * 5): runs when either matches (every 13th and every Friday).
  • crontab -r deletes your whole crontab without asking — r is next to e. Keep a copy: crontab -l > crontab.bak.
Note: systemd timers

Modern alternative to cron: a .timer unit (OnCalendar=*-*-* 02:30:00) triggers a .service, and you get journalctl -u logs and systemctl list-timers. In Kubernetes the same idea is a CronJob (Session 15).

Recap Good automation scripts validate input, log with timestamps, use functions, quote everything, keep going on partial failure but exit non-zero. Schedule with crontab -e (m h dom mon dow command), set PATH, redirect output, escape %, and check grep CRON /var/log/syslog.

★ Putting it all together

The big idea

Shell scripts turn the Session 2 commands into repeatable automation. backup.sh uses arguments + validation, a function per directory, a loop over "$@", a timestamped tar, find -mtime cleanup and logging with tee; healthcheck.sh uses a retry loop, a function whose output is captured, and systemctl for self-healing. cron runs both on a schedule. The same scripting skills reappear in Dockerfile RUN lines, CI pipeline run: steps and Kubernetes probes.

Quick self-check

What does X=5; echo '$X' "$X" "${X}0" print?

$X 5 50 — single quotes are literal, double quotes expand, braces end the name before the 0.

A script is called as ./s.sh "a b" c. How many times does for x in "$@" loop? for x in "$*"? for x in $*?

2 (a b, c), 1 (a b c), 3 (a, b, c).

Why does [ $NAME = admin ] error when NAME is empty? Give two fixes.

It expands to [ = admin ] → "unary operator expected". Quote it ([ "$NAME" = admin ]) or use [[ $NAME = admin ]].

Difference between cmd > out.log 2>&1 and cmd 2>&1 > out.log?

Redirections apply left to right. The first sends stdout to the file, then points stderr at the same place → both in the file. The second points stderr at the current stdout (the terminal) first, then moves only stdout to the file.

Write the cron schedule for "every weekday at 18:30" and for "every 10 minutes".

30 18 * * 1-5 and */10 * * * *.

A backup job works when you run it by hand but does nothing from cron. Name three likely causes.

Minimal PATH (command not found), unescaped % in the crontab line, relying on your shell's environment / current directory, wrong permissions (needs root), or output not redirected so the error was never seen.

Why doesn't healthcheck.sh use set -e, and why should a function return yes/no via exit status but data via echo?

A failing curl is an expected outcome we handle with retries; -e would kill the script before it restarts the service. return only carries a 0–255 status (usable directly in if); strings and numbers must be printed and captured with $(…).
