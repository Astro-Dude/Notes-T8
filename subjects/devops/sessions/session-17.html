1 What is Helm?

Explain like I'm 5

Helm is npm/apt for Kubernetes. A chart is a package of YAML templates; installing it with your settings creates a running copy called a release.

The problem with plain kubectl apply -f k8s/ for TaskFlow:

  • 7 YAML files × dev/staging/prod = copy-pasted folders that drift apart (only replicas, image tag, host and resources really differ).
  • No version for "the app": which set of files is running in prod right now?
  • Rollback means finding old files in Git and re-applying them by hand. No clean "uninstall the whole app".

Helm fixes it: write the YAML once as templates, put the differences in values, and Helm tracks every install/upgrade as a numbered revision.

  • Helm 3+ is client-only: it uses your kubeconfig and your RBAC permissions. Helm 2 needed an in-cluster server, Tiller, usually with cluster-admin rights — a security hole, removed in Helm 3.
Helm 3 vs Helm 4

Helm 4 went GA in Nov 2025 (brew install helm now gives v4.x; Helm 3 still gets patches). Charts (apiVersion: v2) and every command on this page work in both. Differences you'll see in v4: --atomic is renamed --rollback-on-failure (old name still works, with a deprecation warning), --force → --force-replace, and installs use server-side apply by default.

Common mistakes

Recap Chart = package, values = settings, release = installed instance, revision = its version. Helm renders templates locally and stores release state as Secrets in the namespace.

Dependencies (sub-charts) are declared in Chart.yaml too. Example — if TaskFlow shipped its own Postgres instead of the StatefulSet from Session 15:

  - name: postgresql
    version: "18.x.x"                                  # SemVer range of the sub-chart

$ helm dependency update charts/taskflow        # downloads into charts/taskflow/charts/ + writes Chart.lock
Saving 1 charts

Sub-chart values are set under the sub-chart's name in the parent's values: postgresql.auth.database: taskflow.

Common mistakes
  • version: 0.1 → YAML makes it a number: [ERROR] Chart.yaml: version should be of type string but it's of type float64. version: abc → version 'abc' is not a valid SemVer. Use 0.1.0.
  • Bumping only appVersion after editing templates → two different charts share version 0.1.0 in your registry.
  • Committing charts/*.tgz without Chart.lock — commit the lock file, re-download with helm dependency build.
Recap helm create scaffolds the layout. Chart.yaml: apiVersion: v2, name, version (chart SemVer) ≠ appVersion (app release), optional dependencies.

3 values.yaml

Explain like I'm 5

values.yaml is the settings form. Templates read the form; dev and prod fill in a few boxes differently.

charts/taskflow/values.yaml
replicaCount: 2                      # ignored when autoscaling.enabled=true (HPA owns replicas)

image:
  repository: shauryav/taskflow-api
  tag: ""                            # empty → template falls back to Chart.appVersion
  pullPolicy: IfNotPresent

nameOverride: ""
fullnameOverride: "taskflow-api"    # keep object names from Sessions 10–16 (Ingress, NetworkPolicies)

podLabels:
  app: taskflow-api                  # extra pod label: the NetworkPolicies from Session 16 select on it

service:
  type: ClusterIP
  port: 80                           # Service port
  targetPort: 3000                   # container port (Express listens on PORT=3000)

env:                                 # non-secret env vars, rendered with range
  NODE_ENV: production
  LOG_LEVEL: info

database:
  existingSecret: taskflow-db-secret # Secret created outside Helm (kubectl create secret)
  secretKey: DATABASE_URL

podSecurityContext:                  # passes the "restricted" Pod Security level (Session 16)
  runAsNonRoot: true
  runAsUser: 1000
  seccompProfile:
    type: RuntimeDefault

securityContext:
  allowPrivilegeEscalation: false
  capabilities:
    drop: ["ALL"]

resources:                           # copied verbatim with toYaml
  requests:
    cpu: 100m
    memory: 128Mi
  limits:
    cpu: 500m
    memory: 256Mi

autoscaling:
  enabled: false                     # true → hpa.yaml rendered, replicas omitted
  minReplicas: 2
  maxReplicas: 5
  targetCPUUtilizationPercentage: 70

ingress:
  enabled: false                     # true → ingress.yaml rendered
  className: nginx
  host: taskflow.local

Values precedence (exam favourite)

chart's values.yaml  <  parent chart's values  <  -f file1.yaml  <  -f file2.yaml  <  --set / --set-string
   (lowest)                                       (later -f wins)                    (highest)
$ helm template taskflow charts/taskflow -f charts/taskflow/values-dev.yaml --set replicaCount=3 | grep replicas
  replicas: 3      # values.yaml says 2, values-dev.yaml says 1, --set says 3 → 3
  • Maps merge deeply (dev set only resources.requests; limits survived). Lists are replaced as a whole.
  • Remove a default key by setting it to null (e.g. --set ingress.className=null).
  • --set syntax: nested a.b=c, several a=1,b=2, list item hosts[0]=x.
Common mistake: unquoted versions

YAML reads tag: 1.20 as the number 1.2, so the chart deploys shauryav/taskflow-api:1.2 (verified with helm template). Always write tag: "1.20". On the command line, --set-string image.tag=1.20 forces a string.

Recap values.yaml = defaults; values-<env>.yaml = small overrides. Precedence: chart defaults < -f (last wins) < --set. Maps merge, lists replace. Quote tags.

4 Templates

Explain like I'm 5

A template is YAML with blanks like {{ .Values.image.tag }}. Helm fills the blanks from the values and hands normal YAML to Kubernetes.

  • Syntax is Go templates plus the Sprig function library. Everything between {{ }} is evaluated; the rest is copied as is.
  • . (dot) is the current scope; at the top it holds the built-in objects below.
  • {{- trims whitespace/newlines on the left, -}} on the right. Most indentation bugs come from these.
  • Pipelines work like the shell: {{ .Values.env.LOG_LEVEL | upper | quote }} → "INFO".
Built-in objectValue for helm install taskflow charts/taskflow -n taskflow
.ValuesMerged values (defaults + -f + --set)
.Release.Name / .Release.Namespacetaskflow / taskflow
.Release.Revision1 on install, 2 after first upgrade…
.Release.ServiceHelm
.Chart.Name / .Chart.Version / .Chart.AppVersiontaskflow / 0.1.0 / 1.0.0
.Capabilities.KubeVersionCluster version, e.g. to pick an API version

_helpers.tpl — named templates

charts/taskflow/templates/_helpers.tpl
{{/* Chart name, overridable with .Values.nameOverride */}}
{{- define "taskflow.name" -}}
{{- default .Chart.Name .Values.nameOverride | trunc 63 | trimSuffix "-" }}
{{- end }}

{{/* Full name: "<release>-<chart>", or just "<release>" if it already contains the chart name */}}
{{- define "taskflow.fullname" -}}
{{- if .Values.fullnameOverride }}
{{- .Values.fullnameOverride | trunc 63 | trimSuffix "-" }}
{{- else }}
{{- $name := default .Chart.Name .Values.nameOverride }}
{{- if contains $name .Release.Name }}
{{- .Release.Name | trunc 63 | trimSuffix "-" }}
{{- else }}
{{- printf "%s-%s" .Release.Name $name | trunc 63 | trimSuffix "-" }}
{{- end }}
{{- end }}
{{- end }}

{{/* Labels put on every object */}}
{{- define "taskflow.labels" -}}
helm.sh/chart: {{ printf "%s-%s" .Chart.Name .Chart.Version }}
{{ include "taskflow.selectorLabels" . }}
app.kubernetes.io/version: {{ .Chart.AppVersion | quote }}
app.kubernetes.io/managed-by: {{ .Release.Service }}
{{- end }}

{{/* Labels used in selectors — must never change after the first install */}}
{{- define "taskflow.selectorLabels" -}}
app.kubernetes.io/name: {{ include "taskflow.name" . }}
app.kubernetes.io/instance: {{ .Release.Name }}
{{- end }}
  • define "x" creates a named template; include "x" . renders it, passing the current scope . (forget the dot → empty values).
  • trunc 63: Kubernetes names/labels max 63 chars. {{/* */}} comments disappear on render; a # comment would be copied into the output YAML.

deployment.yaml

charts/taskflow/templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "taskflow.fullname" . }}
  labels:
    {{- include "taskflow.labels" . | nindent 4 }}
spec:
  {{- if not .Values.autoscaling.enabled }}
  replicas: {{ .Values.replicaCount }}
  {{- end }}
  selector:
    matchLabels:
      {{- include "taskflow.selectorLabels" . | nindent 6 }}
  template:
    metadata:
      labels:
        {{- include "taskflow.selectorLabels" . | nindent 8 }}
        {{- with .Values.podLabels }}
        {{- toYaml . | nindent 8 }}
        {{- end }}
    spec:
      {{- with .Values.podSecurityContext }}
      securityContext:
        {{- toYaml . | nindent 8 }}
      {{- end }}
      containers:
        - name: {{ .Chart.Name }}
          {{- with .Values.securityContext }}
          securityContext:
            {{- toYaml . | nindent 12 }}
          {{- end }}
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
          imagePullPolicy: {{ .Values.image.pullPolicy }}
          ports:
            - name: http
              containerPort: {{ .Values.service.targetPort }}
          env:
            - name: PORT
              value: {{ .Values.service.targetPort | quote }}
            {{- range $key, $value := .Values.env }}
            - name: {{ $key }}
              value: {{ $value | quote }}
            {{- end }}
            - name: DATABASE_URL
              valueFrom:
                secretKeyRef:
                  name: {{ required "database.existingSecret is required" .Values.database.existingSecret }}
                  key: {{ .Values.database.secretKey }}
          readinessProbe:
            httpGet:
              path: /health
              port: http
          livenessProbe:
            httpGet:
              path: /health
              port: http
          {{- with .Values.resources }}
          resources:
            {{- toYaml . | nindent 12 }}
          {{- end }}
ConstructWhat it does here
include "taskflow.labels" . | nindent 4Render the helper, then add a newline + indent every line by 4 spaces so it sits under labels:.
if not .Values.autoscaling.enabledOmit replicas when an HPA manages it (otherwise every upgrade resets the HPA's count).
with .Values.podLabelsRuns the block only if the value is non-empty, and sets . to it — so toYaml . means toYaml .Values.podLabels.
toYaml . | nindent 12Convert a values map/list to YAML text, indented 12 spaces (under resources:).
.Values.image.tag | default .Chart.AppVersionUse the tag if set, else 1.0.0 from Chart.yaml.
| quoteWraps in double quotes. Env values must be strings: value: 3000 would be rejected.
range $key, $value := .Values.envLoop over the map (keys come out sorted alphabetically).
required "msg" XAbort rendering with msg if X is empty.
{{- on control linesEats the newline before if/end/range so they leave no blank lines.

Common mistake: indent vs nindent

{{- include "taskflow.selectorLabels" . | indent 8 }} — the {{- eats the newline and indent doesn't add one, so the first label lands on the labels: line:

Use nindent after {{-. Debug with helm template --debug (prints the broken YAML) and --show-only templates/deployment.yaml.

5 Install & upgrade

Explain like I'm 5

Common mistakes
  • Values silently reset on upgrade. helm upgrade taskflow ./charts/taskflow --set image.tag=1.2.1 (no -f) builds values from chart defaults + that --set only — dev's 1 replica and debug logging are gone. Helm reuses old values automatically only when you pass no values at all. Always pass the same -f files (or --reuse-values, carefully).
  • Error: INSTALLATION FAILED: Unable to continue with install: Service "taskflow-api" in namespace "taskflow" exists and cannot be imported into the current release: invalid ownership metadata ... — objects created earlier with kubectl apply. Delete them (kubectl delete -f k8s/deployment.yaml -f k8s/service.yaml -f k8s/ingress.yaml) or adopt them with --take-ownership.
  • Error: INSTALLATION FAILED: cannot re-use a name that is still in use → the release exists; use helm upgrade (or upgrade --install).
Recap helm install NAME CHART -n NS -f values --set k=v; then helm upgrade with the same -f files. In CI: helm upgrade --install … --atomic --wait. Inspect with helm list, get values, get manifest.

6 Rollback & release history

Explain like I'm 5

Every upgrade is saved like a game checkpoint. Rollback reloads an old checkpoint — and that reload is itself saved as a new checkpoint.

Scenario: revision 3 deploys a tag that doesn't exist. Pods hit ImagePullBackOff, but the old ReplicaSet keeps serving (rolling update), so you have time:

$ helm upgrade taskflow ./charts/taskflow -n taskflow -f charts/taskflow/values-dev.yaml --set image.tag=1.3.0-typo
Release "taskflow" has been upgraded. Happy Helming!      # no --wait → Helm doesn't check pods!
$ kubectl get pods -n taskflow -l app=taskflow-api
NAME                            READY   STATUS             RESTARTS   AGE
taskflow-api-7c5d8b9f4-q8w2x    1/1     Running            0          9m
taskflow-api-86f7d6c5b9-lm4zt   0/1     ImagePullBackOff   0          50s

$ helm history taskflow -n taskflow
REVISION   UPDATED                    STATUS       CHART            APP VERSION   DESCRIPTION
1          Fri Oct  9 17:20:05 2026   superseded   taskflow-0.1.0   1.0.0         Install complete
2          Fri Oct  9 17:31:40 2026   superseded   taskflow-0.1.0   1.0.0         Upgrade complete
3          Fri Oct  9 17:44:12 2026   deployed     taskflow-0.1.0   1.0.0         Upgrade complete

$ helm rollback taskflow 2 -n taskflow
Rollback was a success! Happy Helming!
$ helm history taskflow -n taskflow
REVISION   UPDATED                    STATUS       CHART            APP VERSION   DESCRIPTION
1          Fri Oct  9 17:20:05 2026   superseded   taskflow-0.1.0   1.0.0         Install complete
2          Fri Oct  9 17:31:40 2026   superseded   taskflow-0.1.0   1.0.0         Upgrade complete
3          Fri Oct  9 17:44:12 2026   superseded   taskflow-0.1.0   1.0.0         Upgrade complete
4          Fri Oct  9 17:47:30 2026   deployed     taskflow-0.1.0   1.0.0         Rollback to 2
ObservationWhy
Rollback created revision 4, not "back to 2"History is append-only; revision 4 is a copy of 2's manifest + values.
helm rollback taskflow (no number)Goes to the previous revision.
Revision 3 says "Upgrade complete" though pods are brokenWithout --wait, success = "API accepted the YAML".
APP VERSION stays 1.0.0 although tags changedIt shows Chart.yaml's appVersion, not --set image.tag. Use helm get values to see the tag.
Status valuesdeployed (current), superseded, failed, pending-install/upgrade/rollback, uninstalled.

Automatic rollback with --atomic

$ helm upgrade taskflow ./charts/taskflow -n taskflow -f charts/taskflow/values-dev.yaml \
    --set image.tag=1.3.0-typo --atomic --timeout 2m
Error: UPGRADE FAILED: release taskflow failed, and has been rolled back due to atomic being set: context deadline exceeded
# Helm 4 wording: "... due to rollback-on-failure being set: ..."
$ helm history taskflow -n taskflow --max 2
REVISION   UPDATED                    STATUS       CHART            APP VERSION   DESCRIPTION
5          Fri Oct  9 17:52:01 2026   failed       taskflow-0.1.0   1.0.0         Upgrade "taskflow" failed: context deadline exceeded
6          Fri Oct  9 17:54:02 2026   deployed     taskflow-0.1.0   1.0.0         Rollback to 4

Where is this history stored?

$ kubectl get secrets -n taskflow -l owner=helm
NAME                             TYPE                 DATA   AGE
sh.helm.release.v1.taskflow.v1   helm.sh/release.v1   1      35m
sh.helm.release.v1.taskflow.v2   helm.sh/release.v1   1      23m
...
sh.helm.release.v1.taskflow.v6   helm.sh/release.v1   1      1m
  • One Secret per revision, in the release's namespace: gzipped + base64 JSON of chart, values and rendered manifest.
  • helm upgrade keeps the last 10 revisions (--history-max).
  • helm uninstall deletes the objects and these Secrets (add --keep-history to keep them). Deleting the namespace wipes the release too.
  • Rollback restores Kubernetes objects only — not database data. A migration that changed the schema must be undone separately.
Recap helm history → pick a revision → helm rollback NAME REV (creates a new revision). --atomic does it automatically. State lives in sh.helm.release.v1.* Secrets.

Helm vs Kustomize

HelmKustomize
ApproachTemplates + valuesPlain YAML base + patches per env (overlays)
ToolingSeparate helm CLIBuilt into kubectl: kubectl apply -k overlays/prod
Logicif, range, functionsNone by design
Packaging & versionsCharts with SemVer, repos/OCIJust folders in Git
Release history / rollbackYes (history, rollback)No — use Git (git revert)
Best forDistributing apps, third-party software (Redis, Prometheus)Small env tweaks to your own manifests

Not either/or: Argo CD (Session 22) deploys Helm charts and Kustomize overlays alike.

Common mistakes
  • Pods stuck CreateContainerConfigError → the taskflow-db-secret Secret is missing in that namespace (Helm doesn't create it).
  • Changing selectorLabels (or the release name) after install → spec.selector: Invalid value ... field is immutable. Selector labels must never change; uninstall/reinstall if you must.
  • Running kubectl edit on Helm-managed objects → the next helm upgrade overwrites your edit. Change values, not live objects.
Recap lint → template (+ server dry run) → upgrade --install --atomic --wait with per-env -f files → verify → rollback if needed. Package and push to an OCI registry to share.

★ Putting it all together

The big idea

TaskFlow's Deployment, Service, Ingress and HPA are now written once, as templates in charts/taskflow. Chart.yaml versions the package, values.yaml holds defaults, and values-dev.yaml/values-prod.yaml hold only the differences. helm upgrade --install --atomic --wait deploys any environment in one command and records a revision, so a bad release is one helm rollback away. CI will run this same command with the new image tag.

Quick self-check

What is the difference between version and appVersion in Chart.yaml?

version is the chart's own SemVer, bumped when templates/defaults change. appVersion is the version of the application inside (TaskFlow 1.0.0), used here as the default image tag.

values.yaml sets replicaCount: 2, values-prod.yaml sets 4, and you run -f values-prod.yaml --set replicaCount=6. How many replicas?

6. --set beats -f files, which beat the chart's values.yaml.

What does {{- toYaml .Values.resources | nindent 12 }} do?

Converts the resources map from values into YAML text, starts it on a new line and indents every line by 12 spaces; {{- trims the whitespace before the action so no blank line is left.

History shows revisions 1–3 (3 deployed). You run helm rollback taskflow 1. What does history show now?

A new revision 4, status deployed, description "Rollback to 1". Revision 3 becomes superseded. Rollbacks never delete history.

Why does Helm 3 not need Tiller, and where does it keep release state?

Helm 3 is client-only: it renders templates locally and talks to the API server with your kubeconfig/RBAC. Release state is stored as Secrets (sh.helm.release.v1.<name>.v<rev>) in the release namespace.

Why use helm upgrade --install --atomic --wait in CI instead of helm install?

upgrade --install works on both the first and later runs. --wait fails the job if pods don't become Ready, and --atomic rolls back automatically, so a broken image never stays deployed.

Your values file has tag: 2.10 and the pod pulls :2.1. Why?

YAML parsed the unquoted 2.10 as a float (2.1). Quote it: tag: "2.10", or use --set-string.
