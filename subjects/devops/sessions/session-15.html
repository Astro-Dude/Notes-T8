1 Namespaces

Explain like I'm 5

A namespace is a folder inside the cluster: the same file name can exist in two folders, and each folder can get its own size limit and access rules.

  • A namespace partitions one cluster: object names must be unique within a namespace (taskflow-api can exist in both taskflow-dev and taskflow-prod).
  • It's the scope for RBAC (S16), ResourceQuota / LimitRange (§3) and NetworkPolicy (S16).
  • Not a security wall by itself: pods in different namespaces can still talk to each other until a NetworkPolicy says otherwise.

Cross-namespace DNS

Short names resolve only in the caller's own namespace. From anywhere else use <service>.<namespace> or the FQDN <service>.<namespace>.svc.cluster.local:

# Prometheus lives in "monitoring" (created in §5) and scrapes the API in "taskflow"
$ kubectl run tmp -n monitoring --rm -it --image=busybox:1.36 --restart=Never -- \
    wget -qO- -T 3 http://taskflow-api.taskflow.svc.cluster.local/health
{"status":"ok"}
pod "tmp" deleted
Common mistakes
  • kubectl delete namespace taskflow deletes everything in it — Deployments, Secrets, PVCs (and with reclaim Delete, the disks). There is no undo.
  • Namespace stuck in Terminating: some object inside has a finalizer that can't complete. kubectl get ns taskflow -o yaml → status.conditions names it.
  • Creating the Secret without -n taskflow → it lands in default and the pod fails with CreateContainerConfigError (Session 14).
Recap Namespaces scope names, RBAC and quotas. Use -n / -A / set-context --current --namespace. Nodes, PVs, StorageClasses are cluster-scoped. Cross-namespace DNS = svc.ns.

2 Requests, limits & QoS classes

Explain like I'm 5

A request is the seat you reserve on the bus; the limit is the most seats you may spread over. The driver (scheduler) only counts reservations.

k8s/deployment.yaml — container resources (excerpt)
          resources:
            requests:            # guaranteed minimum; what the SCHEDULER uses to pick a node
              cpu: 100m          # 0.1 core
              memory: 128Mi      # 128 × 2^20 bytes
            limits:              # hard ceiling, enforced by the kubelet / Linux cgroups
              cpu: 500m          # above this → throttled
              memory: 256Mi      # above this → OOMKilled (exit 137)
UnitMeansExample
CPU 11 vCPU / core / hyperthreadcpu: "2" = two cores
CPU m (millicores)1/1000 of a core250m = 0.25 = a quarter core; 0.1 = 100m
Memory Ki Mi GiPowers of 2 (1Mi = 1,048,576 B)256Mi = 268,435,456 bytes
Memory k M GPowers of 10 (1M = 1,000,000 B)256M ≈ 244Mi
Memory mmilli-bytes (!)256m = 0.256 bytes — a typo that breaks the pod
requestslimits
Used byScheduler (fits if node allocatable − sum of requests ≥ this), HPA %, eviction rankingKubelet + kernel cgroups at runtime
CPU above itAllowed if the node has idle CPUThrottled (CFS quota: 500m = 50 ms per 100 ms) — slower, not killed
Memory above itAllowed, but first in line for eviction under node memory pressureOOMKilled, container restarted
If omittedDefaults to the limit if a limit is set; otherwise 0Unlimited (up to the node)
Worked example: how many API pods fit?

minikube node: allocatable cpu: 2. System pods already request 1050m (see kubectl describe node → Allocated resources). Free = 950m. Each taskflow-api pod requests 100m → 9 pods fit; the 10th is Pending: Insufficient cpu — even if real usage is 2% — because scheduling counts requests, not usage.

QoS classes (exam favourite)

Kubernetes derives a QoS class from requests/limits. Under node memory pressure the kubelet evicts BestEffort first, then Burstable (most over its request first), Guaranteed last.

ClassRuleTaskFlow example
GuaranteedEvery container sets cpu and memory, with requests == limitsPostgres: requests: {cpu: 500m, memory: 512Mi}, limits: {cpu: 500m, memory: 512Mi}
BurstableAt least one request or limit set, but not GuaranteedAPI: requests 100m/128Mi, limits 500m/256Mi
BestEffortNo requests or limits on any containerkubectl run debug --image=busybox:1.36

Setting only limits (cpu + memory) also gives Guaranteed — requests default to the limits.

$ kubectl get pods -n taskflow -o custom-columns='NAME:.metadata.name,QOS:.status.qosClass'
NAME                            QOS
debug                           BestEffort
taskflow-api-7c9d8f6b5d-4kq2x   Burstable
taskflow-db-6b8d9f7c5-k7m2p     Guaranteed
Common mistakes
  • No requests at all: scheduler packs pods blindly, HPA shows <unknown>, pods are BestEffort and die first.
  • Requests = peak usage "to be safe": nodes look full while CPU sits at 5% → Pending pods and wasted money. Request ≈ typical usage, limit ≈ peak.
  • Tight CPU limit on a latency-sensitive API: throttling shows up as slow p95 responses, not errors. Check kubectl top pinned at exactly the limit.
Recap Requests reserve (scheduling, HPA); limits cap (CPU throttled, memory OOMKilled). m = milli, Mi = mebibytes. QoS: Guaranteed (req = lim) > Burstable > BestEffort for eviction survival.

3 ResourceQuota & LimitRange

Explain like I'm 5

ResourceQuota is the namespace's total pocket money. LimitRange is the per-item rule: "nothing over ₹500, and if you don't say a price, assume ₹100."

k8s/quota.yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: taskflow-quota
  namespace: taskflow                 # applies to this namespace only
spec:
  hard:
    requests.cpu: "2"                 # sum of all pods' CPU requests ≤ 2 cores
    requests.memory: 4Gi
    limits.cpu: "4"                   # sum of all CPU limits ≤ 4 cores
    limits.memory: 8Gi
    pods: "20"                        # object counts
    persistentvolumeclaims: "5"
    requests.storage: 50Gi            # total PVC size
    services.loadbalancers: "0"       # no cloud LBs from this namespace (use the Ingress)
    count/deployments.apps: "10"      # count/<resource>.<group> works for any type
KeyLimits
requests.cpu / requests.memorySum of requests of all non-terminal pods in the namespace.
limits.cpu / limits.memorySum of limits.
pods, services, secrets, configmaps, persistentvolumeclaimsNumber of objects.
requests.storageTotal requested PVC storage (per class: gp3.storageclass.storage.k8s.io/requests.storage).
count/deployments.appsGeneric object count for any resource.

k8s/limitrange.yaml
apiVersion: v1
kind: LimitRange
metadata:
  name: taskflow-limits
  namespace: taskflow
spec:
  limits:
    - type: Container
      defaultRequest:                 # injected when a container sets no request
        cpu: 100m
        memory: 128Mi
      default:                        # injected when a container sets no LIMIT
        cpu: 500m
        memory: 256Mi
      min:                            # reject anything smaller
        cpu: 50m
        memory: 64Mi
      max:                            # reject anything bigger
        cpu: "2"
        memory: 2Gi
    - type: PersistentVolumeClaim
      min:
        storage: 1Gi
      max:
        storage: 20Gi                 # no single PVC above 20Gi

Key takeaway

Deploy them as a pair: the quota caps the namespace, the LimitRange gives every pod sane defaults so the quota's "must specify" rule never bites.

Recap ResourceQuota = namespace total (cpu/memory/storage/object counts). LimitRange = per-container min/max + defaults. Both act at admission; quota failures for Deployments show up as ReplicaSet FailedCreate events.

4 StatefulSets

Explain like I'm 5

Deployment pods are identical and nameless; StatefulSet pods have name tags — postgres-0 always comes back as postgres-0, with its own disk.

  • Stable names: <statefulset>-0, -1, -2 — not random hashes.
  • Stable DNS via a headless Service (clusterIP: None): postgres-0.taskflow-db.taskflow.svc.cluster.local.
  • Stable storage: volumeClaimTemplates creates one PVC per pod (data-postgres-0); a rescheduled pod re-attaches to its PVC. PVCs are kept on scale-down/delete (by default).
  • Ordered: created 0 → 1 → 2 (each Running + Ready first), removed 2 → 1 → 0, rolling updates go from the highest ordinal down.
k8s/postgres.yaml (replaces the Session 13 Deployment version)
# --- headless Service: DNS returns pod IPs directly, gives each pod a name ---
apiVersion: v1
kind: Service
metadata:
  name: taskflow-db                   # the API still connects to "taskflow-db:5432"
  namespace: taskflow
spec:
  clusterIP: None                     # headless: no virtual IP, no kube-proxy load balancing
  selector:
    app: taskflow-db
  ports:
    - name: postgres
      port: 5432
      targetPort: postgres
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: postgres                      # pods: postgres-0, postgres-1, …
  namespace: taskflow
  labels:
    app: taskflow-db
spec:
  serviceName: taskflow-db            # MUST name the headless Service → per-pod DNS
  replicas: 1
  podManagementPolicy: OrderedReady   # default; "Parallel" starts all at once
  updateStrategy:
    type: RollingUpdate               # or OnDelete (update only when you delete a pod)
  persistentVolumeClaimRetentionPolicy:
    whenDeleted: Retain               # keep PVCs if the StatefulSet is deleted (default)
    whenScaled: Retain                # keep PVCs of scaled-down pods (default)
  selector:
    matchLabels:
      app: taskflow-db
  template:
    metadata:
      labels:
        app: taskflow-db
    spec:
      terminationGracePeriodSeconds: 30   # time for Postgres to shut down cleanly
      containers:
        - name: postgres
          image: postgres:16
          ports:
            - name: postgres
              containerPort: 5432
          env:
            - name: POSTGRES_DB
              value: taskflow
            - name: POSTGRES_USER
              value: taskflow
            - name: POSTGRES_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: taskflow-db-secret
                  key: POSTGRES_PASSWORD
            - name: PGDATA
              value: /var/lib/postgresql/data/pgdata
          resources:                  # requests == limits → Guaranteed QoS
            requests:
              cpu: 500m
              memory: 512Mi
            limits:
              cpu: 500m
              memory: 512Mi
          readinessProbe:
            exec:
              command: ["pg_isready", "-U", "taskflow", "-d", "taskflow"]
            periodSeconds: 5
          volumeMounts:
            - name: data              # matches volumeClaimTemplates[].metadata.name
              mountPath: /var/lib/postgresql/data
  volumeClaimTemplates:               # one PVC per pod: <template>-<sts>-<ordinal>
    - metadata:
        name: data
      spec:
        accessModes: ["ReadWriteOnce"]
        storageClassName: standard    # gp3 on EKS
        resources:
          requests:
            storage: 5Gi
FieldMeaning
serviceNameHeadless Service that governs the pods' DNS. Without it there are no per-pod names.
clusterIP: NoneDNS for taskflow-db returns the ready pod IPs (A records), plus postgres-N.taskflow-db per pod.
podManagementPolicyOrderedReady (one at a time, in order) or Parallel.
updateStrategyRollingUpdate (highest ordinal first; partition: N updates only ordinals ≥ N — canary) or OnDelete.
persistentVolumeClaimRetentionPolicyRetain (default) or Delete PVCs when the StatefulSet is deleted / scaled down.
volumeClaimTemplatesA PVC template; the controller stamps out data-postgres-0, data-postgres-1…

Common mistakes
  • "replicas: 3 = HA Postgres" — no. You get 3 independent, empty databases; the headless Service would spread queries across them. Replication needs Postgres config or an operator (CloudNativePG, a postgresql-ha Helm chart) or a managed DB (RDS).
  • Switching from the Session 13 Deployment: the new pod gets a new PVC (data-postgres-0) → empty DB. Dump first: kubectl exec deploy/taskflow-db -n taskflow -- pg_dump -U taskflow taskflow > backup.sql, then restore with kubectl exec -i postgres-0 -n taskflow -- psql -U taskflow -d taskflow < backup.sql.
  • Re-applying over the old ClusterIP Service: spec.clusterIPs[0]: Invalid value: []string{"None"}: may not change once set. Delete the old Service, then apply.

5 DaemonSets

Explain like I'm 5

One security guard per building: add a node and a guard appears; remove the node and the guard leaves.

  • A DaemonSet runs exactly one pod on every eligible node. No replicas field — the node count decides.
  • Used for node-level agents: log shippers (Fluent Bit), metrics (node-exporter), CNI (Calico, Cilium, kindnet), kube-proxy, CSI node plugins.
  • Restrict to some nodes with nodeSelector/affinity; include tainted nodes (control plane) with tolerations.

Lab cluster with 3 nodes (kind taints its control-plane node, which makes tolerations visible):

kind-3nodes.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane              # tainted node-role.kubernetes.io/control-plane:NoSchedule
  - role: worker
  - role: worker
$ kind create cluster --name lab --config kind-3nodes.yaml
$ kubectl get ds -A                      # the cluster already runs DaemonSets

kube-system   kindnet      3         3         3       3            3           <none>                   5m
kube-system   kube-proxy   3         3         3       3            3           kubernetes.io/os=linux   5m
k8s/node-exporter.yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: node-exporter
  namespace: monitoring               # kubectl create namespace monitoring
  labels:
    app: node-exporter
spec:
  selector:
    matchLabels:
      app: node-exporter
  updateStrategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1               # replace one node's pod at a time
  template:
    metadata:
      labels:
        app: node-exporter
    spec:
      nodeSelector:
        kubernetes.io/os: linux       # only Linux nodes
      tolerations:
        - key: node-role.kubernetes.io/control-plane
          operator: Exists
          effect: NoSchedule          # also run on the control-plane node
      hostNetwork: true               # listen on the NODE's IP:9100
      hostPID: true                   # see the node's processes
      containers:
        - name: node-exporter
          image: quay.io/prometheus/node-exporter:v1.8.2
          args:
            - --path.procfs=/host/proc
            - --path.sysfs=/host/sys
            - --path.rootfs=/host/root
          ports:
            - name: metrics
              containerPort: 9100
          resources:
            requests:
              cpu: 50m
              memory: 32Mi
            limits:
              memory: 64Mi
          volumeMounts:
            - name: proc
              mountPath: /host/proc
              readOnly: true
            - name: sys
              mountPath: /host/sys
              readOnly: true
            - name: root
              mountPath: /host/root
              readOnly: true
              mountPropagation: HostToContainer
      volumes:                        # hostPath: the legit use case from Session 13
        - name: proc
          hostPath:
            path: /proc
        - name: sys
          hostPath:
            path: /sys
        - name: root
          hostPath:
            path: /
FieldWhy
no replicasOne pod per matching node, automatically.
tolerationsWithout it DESIRED = 2 (workers only) — the control-plane taint repels the pod.
hostNetwork / hostPIDAgent needs the node's real network stack and process table.
hostPath /proc, /sys, /Read the node's CPU, memory, disk and filesystem stats (read-only).
updateStrategyRollingUpdate (default, maxUnavailable: 1) or OnDelete.

6 Jobs & CronJobs

Explain like I'm 5

A Deployment is a shop that's always open. A Job is a delivery — done once it arrives. A CronJob is that delivery booked for every night.

  • A Job runs pods until a given number succeed (exit 0), retrying failures up to backoffLimit (default 6) with back-off 10 s, 20 s, 40 s… (cap 6 min).
  • restartPolicy must be Never or OnFailure (Always is rejected).
  • Finished pods are kept (status Completed) so you can read logs — until ttlSecondsAfterFinished cleans them up.

A database migration Job

k8s/migrate-job.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: taskflow-migrations
  namespace: taskflow
data:
  001_create_tasks.sql: |             # idempotent: safe if the Job retries
    CREATE TABLE IF NOT EXISTS tasks (
      id         SERIAL PRIMARY KEY,
      title      TEXT        NOT NULL,
      done       BOOLEAN     NOT NULL DEFAULT false,
      created_at TIMESTAMPTZ NOT NULL DEFAULT now()
    );
---
apiVersion: batch/v1
kind: Job
metadata:
  name: taskflow-migrate
  namespace: taskflow
spec:
  completions: 1                      # successful pods needed (default 1)
  parallelism: 1                      # pods running at once (default 1)
  backoffLimit: 3                     # after 3 retries (4 pods total) → Job Failed
  activeDeadlineSeconds: 300          # hard stop after 5 min, retries or not
  ttlSecondsAfterFinished: 3600       # auto-delete Job + pods 1 h after finishing
  template:
    spec:
      restartPolicy: Never            # failed pod is kept for logs; Job creates a new one
      containers:
        - name: migrate
          image: postgres:16          # used only for its psql client
          command: ["psql", "-v", "ON_ERROR_STOP=1", "-f", "/migrations/001_create_tasks.sql"]
          env:                        # libpq reads PG* variables
            - name: PGHOST
              value: taskflow-db
            - name: PGUSER
              value: taskflow
            - name: PGDATABASE
              value: taskflow
            - name: PGPASSWORD
              valueFrom:
                secretKeyRef:
                  name: taskflow-db-secret
                  key: POSTGRES_PASSWORD
          resources:                  # required by the quota in §3
            requests:
              cpu: 100m
              memory: 64Mi
            limits:
              cpu: 500m
              memory: 128Mi
          volumeMounts:
            - name: migrations
              mountPath: /migrations
              readOnly: true
      volumes:
        - name: migrations
          configMap:
            name: taskflow-migrations   # each key becomes a file

A nightly backup CronJob

k8s/backup-cronjob.yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: taskflow-backups
  namespace: taskflow
spec:
  accessModes: ["ReadWriteOnce"]
  resources:
    requests:
      storage: 10Gi                   # default StorageClass
---
apiVersion: batch/v1
kind: CronJob
metadata:
  name: taskflow-db-backup
  namespace: taskflow
spec:
  schedule: "0 2 * * *"               # min hour day-of-month month day-of-week → 02:00 daily
  timeZone: "Asia/Kolkata"            # without it: controller-manager's zone, usually UTC
  concurrencyPolicy: Forbid           # don't start if last night's run is still going
  startingDeadlineSeconds: 600        # missed by > 10 min (controller down)? skip this run
  successfulJobsHistoryLimit: 3       # keep 3 finished Jobs (default 3)
  failedJobsHistoryLimit: 1           # keep 1 failed Job (default 1)
  suspend: false                      # true = pause the schedule
  jobTemplate:                        # a normal Job spec, stamped out on each tick
    spec:
      backoffLimit: 2
      activeDeadlineSeconds: 1800
      template:
        spec:
          restartPolicy: OnFailure
          containers:
            - name: pg-dump
              image: postgres:16
              command: ["/bin/sh", "-c"]
              args:
                - >-
                  pg_dump -h taskflow-db -U taskflow -d taskflow -Fc
                  -f /backups/taskflow-$(date +%Y%m%d-%H%M).dump &&
                  find /backups -name '*.dump' -mtime +7 -delete &&
                  ls -lh /backups
              env:
                - name: PGPASSWORD
                  valueFrom:
                    secretKeyRef:
                      name: taskflow-db-secret
                      key: POSTGRES_PASSWORD
              resources:
                requests:
                  cpu: 100m
                  memory: 128Mi
                limits:
                  cpu: 500m
                  memory: 256Mi
              volumeMounts:
                - name: backups
                  mountPath: /backups
          volumes:
            - name: backups
              persistentVolumeClaim:
                claimName: taskflow-backups
FieldMeaning
scheduleStandard 5-field cron (same as crontab, Session 3). Macros @hourly, @daily, @weekly work too.
timeZoneIANA zone name (stable since 1.27). Skip it and "0 2 * * *" runs at 02:00 UTC = 07:30 IST.
concurrencyPolicyAllow (default: overlapping runs OK) · Forbid (skip the new run) · Replace (kill the old run, start the new one).
startingDeadlineSecondsHow late a missed run may still start. Without it, a controller that missed > 100 schedules stops scheduling the CronJob.
jobTemplateExactly a Job's spec (backoffLimit, template, …).
args: - >-YAML folded block: the lines join into one shell command. K8s only expands $(VAR) for defined env vars, so $(date …) reaches the shell untouched.
find … -mtime +7 -deleteRetention: drop dumps older than 7 days.

Common mistakes
  • restartPolicy: Always in a Job → spec.template.spec.restartPolicy: Unsupported value: "Always": supported values: "OnFailure", "Never".
  • Non-idempotent Jobs (e.g. INSERT seed data) + retries = duplicated rows. Make every step safe to run twice.
  • No ttlSecondsAfterFinished / history limits → hundreds of Completed pods clutter kubectl get pods.
  • Backups on a PVC in the same cluster aren't real backups — copy them off-cluster (e.g. aws s3 cp to S3) too.
Recap Job = run to completion (completions, parallelism, backoffLimit, activeDeadlineSeconds, ttlSecondsAfterFinished; restartPolicy Never/OnFailure). CronJob = Job on a cron schedule (timeZone, concurrencyPolicy, history limits). Test with kubectl create job --from=cronjob/….

7 Choosing a workload type

Explain like I'm 5

Pick the controller by asking: does it ever finish, does it need one copy per machine, and does each copy need its own name and disk?

★ Putting it all together

The big idea

TaskFlow now lives in the taskflow namespace with a ResourceQuota (total budget) and a LimitRange (per-pod defaults), so every pod declares requests the scheduler and HPA can use. Each component runs under the controller that fits it: the stateless API as a Deployment, Postgres as a StatefulSet with a stable name, DNS and its own PVC, node-exporter as a DaemonSet on every node, the schema migration as a Job and the nightly pg_dump as a CronJob. Requests and limits decide where pods land, what happens when they overuse resources, and which pods get evicted first.

Quick self-check

A pod has requests: {cpu: 250m, memory: 256Mi} and limits: {cpu: 500m, memory: 256Mi}. What's its QoS class, and what happens at 300Mi and at 700m CPU?

Burstable (CPU request ≠ limit). At 300Mi it exceeds the memory limit → OOMKilled (exit 137). At 700m it's throttled to 500m — slower, not killed.

What's the difference between memory: 512Mi, 512M and 512m?

512Mi = 512 × 2²⁰ = 536,870,912 bytes; 512M = 512,000,000 bytes (~488Mi); 512m = 0.512 bytes (milli) — a typo that makes the container unusable.

After adding a ResourceQuota on requests.cpu, kubectl run tmp --image=busybox is rejected. Why, and what's the clean fix?

With a compute quota, every pod must declare those resources ("must specify requests.cpu…"). Add a LimitRange with defaultRequest/default so pods without resources get defaults injected.

Give three things a StatefulSet guarantees that a Deployment doesn't.

Stable ordinal pod names (postgres-0), stable per-pod DNS via the headless Service in serviceName, and a dedicated PVC per pod from volumeClaimTemplates — plus ordered start/stop/update.

You scale postgres from 3 to 1 replicas. Which pods go first and what happens to their PVCs?

postgres-2, then postgres-1 (reverse ordinal). Their PVCs data-postgres-1/2 are retained (default whenScaled: Retain) and reused if you scale up again.

A 3-node kind cluster shows node-exporter DESIRED = 2. Why?

The control-plane node has the taint node-role.kubernetes.io/control-plane:NoSchedule and the DaemonSet has no matching toleration, so only the 2 workers are eligible.

A CronJob with schedule: "0 2 * * *" and no timeZone runs at 07:30 IST. Why? And what does concurrencyPolicy: Forbid do?

Without timeZone the schedule uses the controller-manager's zone (UTC); 02:00 UTC = 07:30 IST. Forbid skips a new run while the previous Job is still active.
