1 The workflow & kubectl get

Explain like I'm 5

Like a doctor: look at the patient (get), read the chart (describe + events), listen (logs), then examine up close (exec).

kubectl get pods -n taskflow            ← read STATUS, READY, RESTARTS
   │
   ├─ Pending ─────────────────────▶ describe pod → Events: FailedScheduling        (§6)
   ├─ ContainerCreating (stuck) ───▶ describe pod → Events: FailedMount / sandbox
   ├─ ErrImagePull / ImagePullBackOff ▶ describe pod → Events: Failed to pull image  (§5)
   ├─ CreateContainerConfigError ──▶ describe pod → Events: secret/configmap/key     (§5)
   ├─ CrashLoopBackOff / Error / OOMKilled ▶ logs --previous + describe Last State  (§4)
   ├─ Running but READY 0/1 ───────▶ describe pod → Events: Readiness probe failed  (§7)
   └─ Running 1/1, app unreachable ▶ endpoints → selector/targetPort → DNS → ingress (§7)

Still stuck? → kubectl get events --sort-by=.lastTimestamp → exec / debug / port-forward

Pod STATUS cheat sheet

STATUS / READYMeaningFirst command
PendingNot scheduled to a node yet.describe pod → FailedScheduling
ContainerCreatingScheduled; pulling image / mounting volumes / setting up network.describe pod → FailedMount
Init:0/1, Init:CrashLoopBackOffAn init container is running / failing.logs POD -c INIT_NAME
ErrImagePull → ImagePullBackOffImage can't be pulled; kubelet retries with back-off.describe pod
CreateContainerConfigErrorReferenced ConfigMap/Secret/key doesn't exist.describe pod
RunContainerErrorRuntime couldn't start the process (bad command, missing binary).describe pod → Last State message
CrashLoopBackOffContainer keeps exiting; kubelet waits longer between restarts.logs POD --previous
Error / OOMKilledJust exited non-zero / killed for exceeding memory limit.describe pod → Exit Code
CompletedExited 0. Normal for Jobs, a bug for Deployments.check command/CMD
Running + 0/1Process up, readiness probe failing → no traffic.describe pod → Unhealthy
Terminating (stuck)Finalizer or unreachable node.get pod -o yaml → finalizers
Evicted / UnknownNode under disk/memory pressure / node unreachable.describe node

Common mistakes
  • A CrashLoopBackOff pod's phase is still Running — --field-selector=status.phase!=Running won't find it. Read the STATUS column.
  • kubectl get all does not list ConfigMaps, Secrets, Ingresses, PVCs. Ask for them: kubectl get cm,secret,ing,pvc -n taskflow.
  • Forgetting -n taskflow → No resources found in default namespace. — the pods exist, you're looking in the wrong place.
Recap STATUS tells you which tool to reach for. -o wide, -w, -l, -A, -o jsonpath, --sort-by are the flags you'll use daily.

Events

  • Events are API objects (kind: Event) written by the scheduler, kubelet and controllers. Normal = info, Warning = something failed.
  • They're kept for 1 hour by default (kube-apiserver --event-ttl). Old crash? Events are gone — check logs/monitoring.
  • Unsorted by default — always add --sort-by.

4 CrashLoopBackOff & OOMKilled

Explain like I'm 5

The app keeps falling over the moment it stands up. Kubernetes keeps picking it up, but waits a bit longer each time.

  • CrashLoopBackOff is not an error itself — it means "the container exited, and I'm waiting before restarting it again".
  • Back-off delay: 10 s → 20 s → 40 s → 80 s → 160 s → 300 s (cap). Resets after the container runs 10 minutes without crashing.
  • The cause is always in the previous run: logs --previous + Last State exit code.
Exit codeMeaningTypical cause
0 (Completed)Process finished successfullyCMD runs a script that ends; Deployments need a long-running process
1Application errorUncaught exception, missing env var, bad config → read logs
126 / 127Not executable / command not foundTypo in command:, missing binary, CRLF in a shell script
128 (StartError)Runtime couldn't start the processexec: "nodee": executable file not found in $PATH
137 = 128 + 9SIGKILLOOMKilled, or killed after the grace period (failed liveness, ignoring SIGTERM)
143 = 128 + 15SIGTERMNormal stop / liveness restart handled gracefully

k8s/deployment.yaml — broken (v1.2.1, env section)

Common mistakes
  • Running plain kubectl logs after the restart and seeing nothing — the new instance hasn't logged yet. Use --previous.
  • A liveness probe on the wrong port/path also produces CrashLoopBackOff (Exit 137/143, events say failed liveness probe, will be restarted). Fix the probe, not the app.
  • Deleting the pod "to fix it" — the ReplicaSet recreates it with the same broken spec.
Recap CrashLoopBackOff = repeated exits with growing back-off (10 s → 5 min). Read Last State exit code + logs --previous. 137 + OOMKilled = raise the memory limit or fix the leak. rollout undo buys time.

5 ImagePullBackOff & CreateContainerConfigError

Explain like I'm 5

The kubelet went to the shop for your image and came back empty-handed — wrong name, shop was locked, or it already shopped too often today.

  • ErrImagePull = the pull just failed. ImagePullBackOff = waiting before retrying (same 10 s → 5 min back-off).
  • The container never started → kubectl logs has nothing. Everything is in describe pod Events.

Case 1 — tag doesn't exist

6 Pending pods

Explain like I'm 5

The pod is waiting in the lobby because no room (node) fits its booking: too big, wrong kind of room, or its luggage (PVC) hasn't arrived.

  • Pending with an empty Node: = the scheduler couldn't place it. The scheduler writes exactly why into a FailedScheduling event.
  • Read it as: 0/N nodes are available: <count> <reason>, … — one reason per group of nodes. The preemption: part says whether evicting lower-priority pods would help (usually not).
Reason in the eventCauseFix
Insufficient cpu / Insufficient memorySum of requests doesn't fit on any nodeLower requests, add nodes / bigger nodes
pod has unbound immediate PersistentVolumeClaimsPVC is Pendingdescribe pvc (class typo, no matching PV)
didn't match Pod's node affinity/selectornodeSelector/affinity matches no node labelsLabel a node or fix the selector
had untolerated taint {key: value}Node tainted, pod has no tolerationAdd toleration or remove the taint (Session 16)
node(s) didn't have free portshostPort already usedDrop hostPort; use a Service

Isolate the layer with port-forward

TestWorks?Conclusion
kubectl port-forward pod/… 8080:3000 + curl localhost:8080/healthNoApp problem → logs, exec
Pod works, wget taskflow-api/health from tmp pod fails—Service problem → endpoints, selector, targetPort, readiness

Common mistakes
  • Testing the Service from your laptop with curl 10.96.45.12 — ClusterIPs only work inside the cluster. Use a tmp pod or port-forward.
  • pinging a Service IP: ClusterIPs are virtual and usually don't answer ICMP. Test the TCP port with wget/nc.
  • BusyBox nslookup of a short name can print odd NXDOMAIN lines because of search domains; query the FQDN, or use registry.k8s.io/e2e-test-images/jessie-dnsutils:1.3 for dig.
Recap Walk the chain: DNS → Service → endpoints → targetPort → ready pod. <none> endpoints = selector mismatch or no ready pods. Wrong port = connection refused / 502. Cross-namespace = svc.namespace.

★ Putting it all together

The big idea

Every TaskFlow failure leaves a trail: STATUS in get says where it broke, describe + Events say why (scheduler, kubelet, controllers each write their reason), logs --previous shows what the app said before dying, and exec/debug/port-forward let you test each network hop. Fix the manifest in Git, re-apply, and confirm with rollout status — and use rollout undo while you investigate.

Quick self-check

A pod shows CrashLoopBackOff and kubectl logs POD prints nothing. What do you run next?

kubectl logs POD --previous (logs of the crashed instance) and kubectl describe pod POD to read Last State: Terminated → Reason + Exit Code.

Last State shows Reason: OOMKilled, Exit Code: 137. Explain 137 and two fixes.

137 = 128 + 9 (SIGKILL) — the kernel killed the container for exceeding limits.memory. Raise the limit based on measured usage, and/or reduce memory (cap Node heap with --max-old-space-size, fix the leak).

Event: 0/3 nodes are available: 3 Insufficient memory. The nodes show only 30% memory usage in kubectl top nodes. How?

The scheduler uses requests, not actual usage. Already-scheduled pods have requested most of the allocatable memory (see describe node → Allocated resources). Lower requests or add nodes.

kubectl get endpoints taskflow-api shows <none> but the pods are Running 1/1. Most likely cause?

The Service selector doesn't match the pod labels (e.g. app=taskflow vs app=taskflow-api). Verify with kubectl get pods -l <selector>.

What's the difference between ImagePullBackOff and CreateContainerConfigError?

ImagePullBackOff: the kubelet can't fetch the image (tag, auth, rate limit). CreateContainerConfigError: image is fine but the container spec references a ConfigMap/Secret or key that doesn't exist. Both: read describe pod Events; no app logs exist.

From namespace monitoring, wget taskflow-api/metrics fails with bad address, but works from inside taskflow. Fix?

Short names resolve only within the pod's own namespace (search domain). Use taskflow-api.taskflow or the FQDN taskflow-api.taskflow.svc.cluster.local.

A new release crash-loops but users see no outage. Why, and what's the fastest recovery?

RollingUpdate keeps old ReplicaSet pods until new ones are Ready, so the rollout just stalls. kubectl rollout undo deploy/taskflow-api returns to the previous revision immediately.
